# Dishly Recipe Match

[![Release gate](https://github.com/cuhacking-dishly/CU-Hack/actions/workflows/release-gate.yml/badge.svg)](https://github.com/cuhacking-dishly/CU-Hack/actions/workflows/release-gate.yml)

Dishly is a local-first recipe discovery app. A user describes a meal in natural
language, a local Ollama model converts that request into a validated filter,
and a hybrid RAG service retrieves real publisher recipes from Dishly's reviewed
corpus. Recipe titles, ingredients, nutrition, links, and images are never
generated by a model.

The normal runtime has no API key and makes no request to a hosted AI provider.

## What runs locally

```text
React :5173 -> Express :3000 -> Python/FastAPI :8000 -> Ollama :11434
                                      |              |-- qwen3:4b-instruct
                                      |              `-- embeddinggemma
                                      `-- reviewed recipes + vector index
```

- `qwen3:4b-instruct` parses flexible natural language into structured filters.
- Deterministic code overlays explicit allergies, excluded ingredients, vegan,
  cuisines, meal types, and common numeric phrases so obvious constraints cannot
  be silently lost by a small model.
- `embeddinggemma` embeds requests and recipe documents for semantic ranking.
- Allergy/ingredient exclusions and requested vegan are hard filters in exact
  and closest modes. Nutrition and time guide ranking rather than rejecting food.

## Windows quick start

Prerequisites: Node.js 24+, npm 11+, 64-bit Python 3.11+ (3.12 tested), and
[Ollama for Windows](https://ollama.com/download/windows).

```powershell
git clone https://github.com/cuhacking-dishly/CU-Hack.git
cd CU-Hack
npm.cmd ci
npm.cmd run setup
Copy-Item backend/.env.example backend/.env
npm.cmd run dev
```

`setup` creates `dishly-addon/.venv`, installs locked dependencies, starts Ollama,
pulls both local models, validates all reviewed recipes, and builds the vector
index. Open [http://localhost:5173](http://localhost:5173). Readiness is available
at [http://localhost:3000/api/ready](http://localhost:3000/api/ready).

No secret is required. Keep `RETRIEVAL_SERVICE_URL` server-side because the
browser should talk only to Express.

## Commands

| Command | Purpose |
| --- | --- |
| `npm.cmd run setup` | Reproduce dependencies, models, corpus validation, and index. |
| `npm.cmd run dev` | Start Ollama-backed retrieval, Express, and React together. |
| `npm.cmd run test:python` | Lint and test Python with a 90% branch-coverage gate. |
| `npm.cmd run verify` | Run every deterministic Python/backend/frontend/build/browser check. |
| `npm.cmd --prefix backend run test:live` | Exercise the real local Ollama parse/search/detail path; requires retrieval running. |

The same release gate runs on Linux for every pull request and every push to
`main`. In addition to the local matrix, it validates the OpenAPI and deployment
schemas, builds the exact Render retrieval image, validates its embedded corpus,
and starts the packaged Ollama CLI. Failed browser traces, screenshots, and
videos are retained as workflow artifacts.

## Raspberry Pi

The runtime is ARM64-compatible and local. See
[Raspberry Pi deployment](./dishly-addon/docs/PI_DEPLOYMENT.md) for hardware
expectations, setup, systemd, Nginx, validation, and offline-operation checks.
`qwen3:4b-instruct` is about 2.5 GB and is intended for an 8 GB Pi-class machine;
the parser model is configurable if a smaller device needs a smaller local model.

## Project map

```text
backend/        public Express API, validation, state, and contract tests
frontend/       React/Vite interface and browser tests
dishly-addon/   local parser, RAG retrieval, reviewed corpus, and learning guide
deploy/pi/      production service and Nginx templates for Raspberry Pi
scripts/        reproducible Windows/Linux setup and verification
```

Local development stores goals and swipes in memory with no database setup.
Production can set `DATABASE_URL` to use the checked-in PostgreSQL repository and
`REQUIRE_PERSISTENT_STORE=true` to fail readiness rather than silently falling
back to process-local state.
